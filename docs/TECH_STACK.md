# Technology evaluation

**Status:** researched recommendations, not accepted choices. Current as reviewed on 2026-10-24; re-check official project documentation before implementation because APIs and versions change. Suitability ratings are qualitative engineering judgment, not benchmark results. Numeric performance is unknown until measured on target hardware.

## Character compatibility evaluation

VRM is not a universal model container. It is based on glTF and adds avatar conventions such as humanoid mappings, expressions, metadata, and secondary-motion features. Generic glTF can carry meshes, skins, and animation keyframes, but the glTF specification explicitly leaves playback behavior to runtimes; app conventions would be required. VRM assets can declare licensing and avatar-use conditions; preserve/show that metadata and do not treat format support as permission to redistribute. An MVP importer should accept only one selected version and a limited feature profile, reject or warn on unsupported required extensions, bound geometry/textures/file size, and avoid arbitrary scripts. The renderer choice and VRM library compatibility must be demonstrated by a prototype before accepting ADR-002.

## Research limits

Primary documentation establishes API/format capabilities but cannot establish Wowie-specific compatibility, performance, packaging success, user trust, false-positive rates, or license compliance for a chosen dependency set. Those require implementation experiments and review in later phases. Source links are authoritative project/specification documents; version-specific claims should be refreshed before implementation.
